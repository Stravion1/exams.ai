# Cramly: AI study assistant

A dark, neon-green landing page for an AI study assistant, plus a working demo
app: a library of uploaded files, a tutor chat that cites page numbers,
spaced-repetition flashcards and practice quizzes.

The tutor and the study packs are generated by a real language model as soon as
`AI_API_KEY` is set (any OpenAI-compatible endpoint, Z.ai by default). With no
key the app falls back to hand-written study packs, so it still runs offline.

```sh
bun install
bun run dev        # http://localhost:5333
bun run typecheck
bun run build
```

## Connect the model

1. Get an API key. The default endpoint is [Z.ai](https://z.ai) (`glm-4.6`); any
   OpenAI-compatible provider works.
2. Copy `.dev.vars.example` to `.dev.vars` and fill it in:

   ```sh
   AI_API_KEY=your-key
   AI_MODEL=glm-4.6
   AI_BASE_URL=https://api.z.ai/api/paas/v4
   ```

3. Restart `bun run dev` and check `curl localhost:5333/api/ai/status`.

`AI_BASE_URL` and `AI_MODEL` are optional. To use another provider, change both,
for example `https://api.openai.com/v1` with `gpt-4o-mini`, or
`https://openrouter.ai/api/v1` with `anthropic/claude-3.5-sonnet`.

For a deployed Worker, set the same names as secrets:

```sh
npx wrangler secret put AI_API_KEY
npx wrangler secret put AI_MODEL
npx wrangler secret put AI_BASE_URL
```

`.dev.vars` is git-ignored. Never commit a key.

What changes when a key is present:

- `POST /api/upload` has the model write the document's summary, key points,
  flashcards and quiz (from the extracted text of `.txt`/`.md` files, otherwise
  from the file name and subject). The pack is stored on the document, so the
  flashcard and quiz screens show real material.
- `POST /api/chat` has the model answer the student, grounded in that document
  and the conversation so far. If the provider fails, the route returns 502
  with the provider's own message instead of pretending to answer.
- With no key, both routes fall back to the hand-written packs in
  `src/shared/packs.ts`.

## Where things live

- Copy, plans, FAQ and image paths: `src/content.ts`. Every photo and render goes through `IMAGES`, so swap in your own files in `public/images/` from one place.
- The model connection: `src/worker/ai.ts` (config, prompts, JSON parsing, errors). Study packs the app ships with: `src/shared/packs.ts`. `packForFile` picks a fallback pack for an upload; `answer` is the offline tutor.
- Form rules shared by the page and the Worker: `src/shared/validate.ts`.
- Tokens (colours, radii, shadows, motion): `src/styles.css`. Components: `src/components/`. Sections of the landing page: `src/sections/`. Pages: `src/pages/` (app screens in `src/pages/app/`).
- App state (library, card progress, quiz history, chats, user, streak days): `src/lib/library.ts`, saved in localStorage under `cramly:`. The account menu in the app has "Reset demo data".

## Worker routes

All in `src/worker/index.ts`. Each validates its input and answers JSON; nothing is stored server-side.

| Route | Body | Answers |
| --- | --- | --- |
| `GET /api/health` | | `{ ok: true, ai: boolean }` |
| `GET /api/ai/status` | | `{ configured, mode: 'live' \| 'demo', model }`; add `?probe=1` to make one real call and report `probe: 'ok' \| 'failed'` |
| `POST /api/upload` | `{ name, size, text? }` | 200 with a document and its pack (`pack` when the model built it), 422 for a wrong type or size, 502 when the model fails |
| `POST /api/chat` | `{ packId?, context?, message, history? }` | 200 with `{ reply: { text, cite, suggestions }, ai }`, 404 unknown document, 422 empty question, 502 when the model fails |
| `POST /api/signup` | `{ name, email, password, level, terms }` | 200 with the user, 422 with field errors |
| `POST /api/login` | `{ email, password }` | 200 with the user, 422 with field errors |
| `POST /api/subscribe` | `{ email }` | 200 or 422 |
| `POST /api/contact` | `{ name, email, message }` | 200 or 422 |
| anything else under `/api/` | | 404 JSON |

`context` is `{ title, subject, summary, keyPoints }` and lets a model-built pack
be answered without the server storing it; `history` is the last turns of the
thread so follow-up questions work.

## Still demo-only

- Reading actual PDF/Word/slide content server-side. Today only `.txt`/`.md` text
  is extracted (in the browser); other uploads are described from their name.
- Sign-in: `/api/login` and `/api/signup` validate the shape only, and the
  library lives in localStorage rather than a database.
- Payments, newsletters and the contact form accept the submission and discard it.
